# Git Workspace for Codex

**Локальный Git прямо в Codex.** Просматривайте изменения и управляйте коммитами нескольких репозиториев из одной панели.

[Возможности](#возможности) · [Установка](#установка) · [Начало-работы](#начало-работы) · [История изменений](CHANGELOG.md) · [Конфиденциальность](#конфиденциальность) · [Разработка](#разработка)

> Для Codex на macOS. Для запуска требуются Git и Node.js 22+.

## Возможности

- **Несколько репозиториев** — выберите папку с проектами.
- **Карточки репозиториев** — переключайтесь между найденными проектами и сразу видьте активную ветку и число изменённых файлов.
- **Changes и Staged Changes** — просматривайте diff, добавляйте и убирайте файлы из staging.
- **Diff и файл целиком** — переключайте контекст просмотра, смотрите счётчики добавленных и удалённых строк и открывайте выбранный файл из панели diff.
- **История коммитов** — просматривайте граф, фильтруйте историю по ветке и открывайте список файлов и diff выбранного коммита.
- **Commit и Push** — проверьте направление перед отправкой.
- **Сообщения коммитов** — генерация через Codex CLI; модель, язык и формат настраиваются отдельно.
- **Новый репозиторий** — инициализируйте Git и подключите GitHub remote.

Полный список изменений по версиям — в [CHANGELOG.md](CHANGELOG.md). История версий и загрузка релизов доступны на странице [Releases](https://github.com/w1z2z/git-workspace-for-codex/releases).

## Установка

После публикации репозитория в GitHub:

```sh
codex plugin marketplace add w1z2z/git-workspace-for-codex
codex plugin add git-workspace@git-workspace-local
```

Перезапустите Codex (**⌘Q**) и откройте Git Workspace в разделе плагинов. Если установка по GitHub slug не работает в вашей версии Codex, скачайте ZIP, распакуйте его и укажите путь к папке:

```sh
codex plugin marketplace add "/путь/к/git-workspace-for-codex"
codex plugin add git-workspace@git-workspace-local
```

Сборка уже включена, npm для установки не нужен.

## Начало работы

1. Откройте Git Workspace и нажмите **Папка…**.
2. Выберите папку с проектами и репозиторий.
3. Нажмите на строку файла, в том числе на счётчик строк, чтобы открыть diff. В панели просмотра можно переключиться на **Весь файл** или нажать **Открыть файл**.
4. **+** добавляет файл в Staged Changes; **−** убирает.
5. Напишите сообщение или нажмите кнопку со звёздами для генерации.
6. Нажмите **Commit**, затем **Push**, чтобы отправить коммит.

Если staging пуст, Commit включает все изменения репозитория. Если в staging уже есть файлы — коммитятся только они. Для подключения GitHub сначала создайте пустой репозиторий, затем добавьте его HTTPS или SSH URL в плагине.

В широкой панели перетащите границу между списком файлов и diff, чтобы изменить ширину колонок. В узкой панели diff открывается на всю ширину, а кнопка **К файлам** возвращает к списку.

Во вкладке **История** выберите коммит в графе, затем файл, чтобы посмотреть его изменения в этом коммите.

## Настройки генерации

- **Язык приложения** — язык интерфейса.
- **Язык текста коммита** — язык сообщения.
- **Формат** — `feat: add login` (Conventional Commit) или `Add login` (краткая тема).
- **Модель** — модель Codex для генерации.

Генерация требует Codex CLI и активного входа. API-ключ не нужен. Остальные функции работают без Codex CLI.

## Конфиденциальность

- Плагин работает с выбранными локальными Git-репозиториями.
- При генерации diff изменений передаётся Codex CLI; размер ограничен 250 КБ.
- Codex CLI запускается в read-only sandbox. Плагин не читает файлы авторизации.
- Push запускается только по нажатию; направление можно проверить перед отправкой.
- Автоматические fetch и pull не выполняются. Force push, merge и rebase не поддерживаются.
- Отмена изменений файла сохраняет его копию в локальном Git stash после подтверждения.
- Настройки и черновики хранятся в `~/Library/Application Support/Git Workspace/`.

## Разработка

```sh
npm ci
npm run build
npm test
```

Собранные файлы для установки находятся в `dist/`. После изменений исходников команды выше обновляют сборку и запускают тесты на временных Git-репозиториях.

## Удаление

```sh
codex plugin remove git-workspace@git-workspace-local
```

Настройки и черновики в `~/Library/Application Support/Git Workspace/` удаляются отдельно.
